## 范围与接口

新增 `car_knowledge_rag/file_hash.py`，只使用 Python 标准库，不新增依赖。

```python
sha256_file(path: Path, *, chunk_size: int = 1024 * 1024) -> str
register_file(path: Path, *, root: Path, chunk_size: int = 1024 * 1024) -> dict
```

前者返回 64 位十六进制 SHA-256；后者返回 `path`、`size_bytes`、`sha256`。
登记函数的相对输入路径相对于 root；绝对输入路径也必须位于 root 内。
输出路径相对于解析后的 root，统一用 `/` 分隔，不记录本机绝对路径。
root 是由调用者指定的可信资料目录，不自动推断或扫描。

没有新增 CLI、回执解析、批量清单、重复报告、校验命令或原始资料上传。
两函数只读文件、返回结果，不向磁盘写登记记录，不重跑 B2，也不选择有效数据版本。

## 关键代码解说

```python
digest = hashlib.sha256()
size = 0
with path.open("rb") as stream:
    while chunk := stream.read(chunk_size):
        digest.update(chunk)
        size += len(chunk)
return size, digest.hexdigest()
```

- `rb`：读取原始字节，不解码文字，也不转换换行；编码或换行不同可能导致哈希不同。
- `with`：成功或异常时都关闭文件。
- `chunk := ...`：每次读取一块，赋值后判断是否为空；读到文件末尾时结束。
- `update`：将每块内容依次加入同一个哈希计算，不是分别计算各块哈希后拼接。
- 大小是同一轮读取的字节数；默认每块 1 MiB，文件再大也不要求整体放入内存。
- `hexdigest`：最终的十六进制内容指纹。文件名不参与计算，文件内容才参与。

登记时先解析真实路径，再通过 `relative_to(root)` 限定目录边界。
因此 `../` 或指向外部的符号链接不能把目录外文件登记为目录内文件；
内部符号链接会使用解析后的目标路径，不保留别名。
这不是并发文件系统的安全沙箱，读取时应使用已经完成、不会被其他进程修改的 B2 文件。
当前不提供文件锁或原子快照，也不保证能发现读取过程中被并发修改的文件。

## 错误行为

| 情况 | 行为 |
| --- | --- |
| chunk_size 为 0 或负数 | ValueError |
| 文件不存在 | FileNotFoundError，不创建占位文件 |
| 文件在 root 外 | ValueError |
| root 不是目录 | NotADirectoryError |
| 将目录当文件读取 | OSError 的相应子类 |
| 文件不可读或其他磁盘错误 | 异常传给调用者，不返回伪成功记录 |

空文件可以计算有效 SHA-256，大小为 0；这不代表 B2 的空页面是合格资料。
内容有效性与字节指纹是不同的检查。批量处理时如何登记错误留到 B3.2。
