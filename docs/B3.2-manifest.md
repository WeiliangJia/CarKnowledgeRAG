## 如何运行

从项目根目录执行；不访问官网，不调用模型：

```powershell
& .\.tools\uv\bin\uv.exe run --locked --python-preference only-system --no-python-downloads --cache-dir .uv-cache python -m car_knowledge_rag.manifest
```

默认读取 `data/raw/zeekr/`，在 `data/manifests/zeekr/<UTC时间>/` 新建：

- `manifest.json`：来源关联、运行/页面状态、文件路径、大小、SHA-256 和问题列表。
- `duplicates.json`：字节完全相同的文件分组和额外副本数量。

可通过 `--raw-root`、`--output-root` 指定目录。输出不得位于 raw 根目录内，
避免把生成结果混入原始资料。每次创建独立目录，文件使用独占写入，不覆盖旧清单。
中途被终止或磁盘写入失败时可能留下不完整输出目录，不能只凭目录存在判断生成成功。

退出码：无登记问题为 0；发现登记问题且已保存报告为 1；参数错误由 argparse 返回 2。
无有效运行会报告问题，原始根目录不存在等基础文件系统异常直接失败，不伪造空的合格清单。

## 清单字段与状态分工

| 位置 | 字段/内容 | 含义 |
| --- | --- | --- |
| runs | total、failed 等 | 原始运行声明及对应回执路径 |
| pages | capture_status | 运行摘要中的采集状态，保持原值 |
| pages | page_receipt_status | 单页回执中的采集状态；缺失或无效时为 null |
| pages | receipt_matches_summary | 两份记录是否一致；不一致时列入 issues，不自动选择一份覆盖另一份 |
| pages | URL、时间、版本、kind | 页面来源与回执关联 |
| files | path、run_id、role | 相对于所提供 raw 根目录的路径、运行归属及文件角色 |
| files | file_status | registered、missing 或 unreadable_or_unsafe |
| files | capture_status、source_url | 来自运行摘要的关联；运行级文件或未关联文件可为 null |
| files | size_bytes、sha256 | 文件读取成功才填写 |
| issues | code、path | 缺失、非法 JSON、回执冲突、空的成功内容文件、越界、未引用文件等 |

路径使用 `/`，不在 JSON 清单中写本机绝对根目录；迁移时由调用者提供相应 raw 根目录。
文件读取失败不登记假哈希；空文件本身有合法哈希，但成功页面的空内容文件会额外报告问题。
回执声明的文件只接受 B2 的三个固定内容文件名，模型 ID 和页面类型也先做格式校验，
不使用回执中的任意路径读目录外文件。原始 JSON 文件会作为文件登记，但不把其合法 JSON
等同于官方来源认证或完整车辆数据校验。

**registered 不等于采集成功。**例如 B2 的 8X 超时留下了 `response.html`，
它仍可计算哈希，但关联的 capture_status 必须保持 failed。
本次是对现存内容建立基线，不是拿旧清单检查后续变更；后者留到 B3.3。

## 重复报告的口径

对所有已成功读取的文件分组，包含内容文件、来源目录副本和回执。
每组给出哈希、单文件大小和全部相对路径；额外副本数是每组文件数减一后求和。
报告不选择保留项、不删除、不移动、不合并，不将历史失败升级为成功。
来源与采集状态可通过 manifest 中同路径记录回查。

仅比较字节，不做文字规范化或语义去重。即使页面文字相同，动态 DOM 标识也可能导致 HTML 哈希不同；
初始 HTML 相同也可能只是不同页面共用的 JavaScript 外壳，不能推断配置相同。
