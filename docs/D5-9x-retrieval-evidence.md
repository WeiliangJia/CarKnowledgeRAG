# D5 极氪 9X 检索证据标注

D5 把 C7 题目引用的原文位置映射到 D4 的片段 ID。配置表和产品页必须与 C7 引用的快照一致。映射在本地完成。

```powershell
& .\.venv\Scripts\python.exe -m car_knowledge_rag.map_retrieval_evidence data/corpus/9x-d4-chunks.json --split dev --output data/corpus/9x-d5-dev-labels.json
```

默认使用开发集，将结果写入一个新文件。保留测试集可在最终验收时显式指定 `--split test`。换一种切分方案时，对新片段重新生成映射。报告包含题集和片段文件的 SHA-256，供评测运行时确认对应版本。[C7 题集](C7-9x-evaluation.md) · [D4 片段格式](D4-9x-chunking.md)

| 标注 | 映射规则 |
| --- | --- |
| 配置表行列 | 按指定行号和列号定位单元格。同名版本按列号分别匹配。 |
| 编号脚注 | 从该引用涉及的单元格片段中查找实际保留脚注的候选。 |
| 配置图例 | 匹配包含标配、选装、无该配置三种符号说明的公告片段。 |
| 产品页行号 | 将闭区间展开为原文行。某一行出现在多条片段时，均列为候选。 |
| 整份产品页 | 记录为 `scope_references`，供人工复核资料缺项时参考。 |

`evidence_units` 保存每个原文位置及其候选 `chunk_ids`。后续召回评测可用前 K 条结果与候选 ID 求交集。命中同一证据的多个候选只计一次。以现有 C7 标注计算完整命中时，须覆盖该题所有已标注位置。部分位置用于提供背景，问答是否通过仍按 C7 判定规则评分。需遍历全量配置的题目可用 `category` 识别，分别报告 SQL 筛选与文档召回表现。

若有未映射证据，报告保留空候选及原文位置，命令返回 1，方便定位切分缺口。格式或快照错误时返回 2。D5 结果用于验证片段覆盖，召回质量将在 Qdrant 检索可运行后测量。

验收覆盖开发集 96 道题的 396 个证据位置，全部有对应片段。另保留 5 条整页范围标注。空气悬架题 Q07 的原文跨两个片段，快充题 Q09 的配置与脚注 2 命中同一片段。删除快充片段的测试副本会报告该题的配置和脚注均缺失。重复导出字节一致。pytest 通过 95 项和 11 个子测试，1 项既有测试跳过。Ruff 检查通过。
