# D9 极氪 9X 检索基线

D9 读取 C7 开发题、D5 标注和已有 D8 集合。入口校验题集和片段文件哈希，重算标注映射并核对索引里的全部片段 ID、载荷、模型和维度。[D5 证据标注](D5-9x-retrieval-evidence.md) · [D8 向量索引](D8-9x-qdrant-index.md)

```powershell
& .\.venv\Scripts\python.exe -m car_knowledge_rag.evaluate_retrieval --output data/corpus/9x-d9-dev-retrieval.json
```

命令用 `OPENAI_EMBED_API_KEY` 将开发题的问题和已有上下文批量向量化。D5 标注和标准答案留在本机。每道题用同一个查询向量对本机 Qdrant 做精确余弦检索。每次查询返回前 10 条，取其前缀计算 Top-5。

## 判定方法

- **完整证据命中率。** 每个 D5 证据位置只计一次。只要前 K 条结果包含该位置的任一候选片段，就算该位置命中。题目所有标注位置都命中才算完整。整页范围引用不计入这项指标。全量筛选题单独报告，以便区分文档检索和 SQL 遍历题。
- **版本对照。** 只对题目或已有上下文明示单一五座或六座 Ultra 的题重跑。版本选择仅从用户输入取得，多版本比较、集合筛选和版本未定的题只跑基线。过滤要求配置片段同时符合 `version.group` 和 `version.label`，共用的产品正文、公告和图例仍可检索。
- **混入率。** 以对照题数为分母。如果某道题的前 K 条结果有至少一个另一座位版本的 Ultra 配置片段，该题记为混入。比较项记录过滤前后完整命中率及变化题号。

报告还包含逐题的片段 ID、排名、相似度、版本、缺失证据位置和耗时，以及嵌入请求用量。它衡量 D5 所标原文位置的严格覆盖，回答正确率和近似向量索引表现留待相应阶段测量。

## 实测结果

| 无版本过滤的完整命中 | Top-5 | Top-10 |
| --- | ---: | ---: |
| 全部开发题 | 25/96（26.04%） | 36/96（37.50%） |
| 文档和配置题 | 24/83（28.92%） | 31/83（37.35%） |
| 全量筛选题 | 1/13（7.69%） | 5/13（38.46%） |

| 指定版本 | 混入率 @5，过滤前 → 后 | 混入率 @10，过滤前 → 后 | 完整命中 @5，前 → 后 | 完整命中 @10，前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 五座 Ultra | 9/9 → 0/9 | 9/9 → 0/9 | 3/9 → 3/9 | 3/9 → 3/9 |
| 六座 Ultra | 7/7 → 0/7 | 7/7 → 0/7 | 1/7 → 2/7 | 2/7 → 3/7 |
| 合计 | 16/16 → 0/16 | 16/16 → 0/16 | 4/16 → 5/16 | 5/16 → 6/16 |

过滤让 Q23 在 Top-5、Q08 在 Top-10 转为完整命中，两种 K 均未观察到完整命中退化。在 83 道文档和配置题中，无过滤 Top-10 有 27 道题仅缺配置图例。该缺失反映当前纯向量召回和 D5 严格判分口径。

正式运行的 96 个查询向量共使用 3,184 个输入 token。修正版本对照规则后用同样的输入重跑，初次核对也使用 3,184 个输入 token。全量 pytest 通过 112 项和 11 个子测试，1 项既有测试跳过。Ruff 检查通过。
