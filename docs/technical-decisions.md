## ADR-001：Python 与可复现环境

- **背景**：学习重点是车辆数据处理与 RAG；本地为 Windows，云端计划为 Linux。
- **决定**：后端使用 Python 3.11、uv 和 `uv.lock`；依赖按步骤引入，开发工具放在 dev 组。
- **替代方案**：全部使用 TypeScript 后端；仅用全局 Python 与未锁定的 pip 安装。
- **收益与代价**：主线围绕 Python 生态展开，锁文件帮助复现；仍需维护 Python 版本和跨平台兼容性。
- **证据与复查**：A4～A7 已实现，`pyproject.toml` 和锁文件是依据。
  升级 Python 或依赖时重新跑现有测试与 Linux CI，不因有锁文件就假定所有平台行为一致。

## ADR-002：React 与 TypeScript 前端

- **背景**：用户希望实践 React/TypeScript 与 ESLint，界面需要问答、比较表及引用展示。
- **决定**：React + TypeScript + Vite；规划采用 Ant Design、fetch 和 React 内置状态。
  ESLint 检查前端代码，tsc 检查类型，Prettier 统一格式；Python 继续使用 Ruff。
- **替代方案**：此前提出的 Streamlit、FastAPI + Jinja2；当前不引入 Next.js 或 Redux。
- **收益与代价**：满足前端学习与交互需求，静态构建产物可由 Caddy 提供；
  需要额外维护 Node、前端依赖与前后端接口类型。
- **验证或复查**：页面阶段验证登录、比较表、引用和错误状态；
  只有出现实际的服务端渲染或复杂状态需求时再讨论新增框架。

## ADR-003：FastAPI 与简单应用结构

- **背景**：需要类型明确的问答 API、个人登录和独立的数据处理命令。
- **决定**：规划采用 FastAPI、Uvicorn、Pydantic；首版一个后端应用，不提前拆微服务。
  已实现配置校验和标准库 logging；启动先校验配置，后初始化日志。
- **替代方案**：Django 全栈、Flask、自定义 Web 框架；第三方日志框架。
- **收益与代价**：配置、类型与业务接口可逐步衔接；授权、输入边界和异常处理仍需自己实现。
  标准日志已满足当前范围，但不自动脱敏，也尚未接入请求标识或 CloudWatch。
- **验证或复查**：后续接口测试验证无效输入、未登录访问、会话隔离与失败响应；
  只有标准库无法满足明确需求时才增加日志依赖。

## ADR-004：关系数据库与 ORM

- **背景**：电池、续航、配置状态、版本与条件筛选需要精确、完整的事实查询。
- **决定**：PostgreSQL + SQLAlchemy 2.x + psycopg；Alembic 管理结构变更。
  先采用同步访问、简单 ORM 与参数化 SQL，不增加通用多层 Repository/Service 封装。
- **替代方案**：SQLModel 可减少部分模型代码；Django ORM 需要配合另一套应用框架。
  SQLModel 不是已采用方案，未把关系数据迁移到向量库。
- **收益与代价**：明确掌握事务、关系与迁移；需要区分数据库模型和 API 模型，维护部分重复定义。
- **验证或复查**：存储阶段检查导入幂等、选装条件、单位、比较及筛选；
  并发成为实测瓶颈后再讨论异步访问，不预先承诺性能。

## ADR-005：保留 Qdrant

- **背景**：此前曾提议用 PostgreSQL + pgvector 减少常驻服务；用户随后明确要求继续使用 Qdrant。
- **决定**：PostgreSQL 保存结构化事实，Qdrant 保存片段向量及过滤元数据，通过稳定标识与数据版本关联。
- **替代方案**：pgvector 合并存储；当前不作为主线，也不同时维护两套向量数据库。
- **收益与代价**：保留独立向量数据库的学习实践；增加内存、运维、备份及跨存储一致性处理。
- **验证或复查**：实测召回、过滤、内存和恢复；更换该主线需要先说明证据并取得用户允许。
  Qdrant 不仅能做稠密检索，当前架构只约定我们先使用其稠密向量路径。

## ADR-006：官方资料与离线快照

- **背景**：用户要求覆盖极氪中国官网采集时展示的全部车系及版本，不在问答时实时搜索。
- **决定**：Playwright 正常加载公开动态页面，HTTPX 下载已发现的公开文件；
  解析后保存市场、官方批次代码、版本、座位、电池条件、脚注、来源和快照。
  使用结构解析、pandas 检查与 Pydantic 校验，关键数值人工核验；PDF/OCR 按实际资料引入。
- **替代方案**：第三方汽车平台补齐、实时联网、只抓静态 HTML、全部转图片 OCR。
  第三方来源不默认进入知识库，需先报告缺口并经用户允许。
- **收益与代价**：来源统一、回答可追溯；官网变化需要维护解析，快照存在时效性与资料缺失。
- **验证或复查**：A3 的 2026-10-15 调查为历史线索，正式采集前重新核对。
  等待配置表实际加载，明确资料缺失与加载失败；不推断自然年款或实际订单可选性。

## ADR-007：先理解流程，再接入 LlamaIndex

- **背景**：目标包括理解 RAG 原理，不能只得到一个框架黑箱。
- **决定**：先手写最小切分、嵌入、召回与证据生成，再使用 LlamaIndex 的 Document/Node、
  切分与检索组件；配置表保留行列关系，正文使用适合的文本切分方式。
- **替代方案**：直接使用托管 Knowledge Bases；LangChain/LangGraph；所有资料固定长度切分。
  这些不同时进入主线依赖，托管方案或其他框架可留作后续比较。
- **收益与代价**：既能解释底层又能学习框架；需要维护手写基线与框架映射，避免做两套完整业务系统。
- **验证或复查**：同一开发集比较切分、表格完整性、来源保留和效果；
  切分或嵌入变化时重新建立对应索引，不混用旧片段。

## ADR-008：精确查询与混合检索分工

- **背景**：车型编号需要精确匹配，功能解释存在同义问法，完整筛选不能依赖 Top-K。
- **决定**：配置查询、排序、筛选使用受控 SQL；文档检索结合 BM25 与 Qdrant 稠密向量，
  用 RRF 融合排名，按需测试重排。关键词主线先用 LlamaIndex BM25 集成；
  中文分词、字段处理、Top-K 和重排不在此固定参数。
- **替代方案**：只用向量、只用关键词、让模型任意生成并执行 SQL、直接相加两种不同尺度的分数。
  OpenSearch 作为本地搜索引擎专题，不默认购买托管服务或在云端常驻。
- **收益与代价**：兼顾关键词与语义，保留精确查询；多路检索增加延迟与调参工作，不保证必然提升。
- **验证或复查**：比较各路单独与融合的召回、版本误匹配、正确率、延迟和成本；
  每轮实验先提出假设并获得允许，效果不足的组件不因“更复杂”就保留。

## ADR-009：模型首选与调用平台

- **背景**：需要中文证据问答与向量化，同时希望学习 AWS 权限和费用管理。
- **决定**：首选通过 Bedrock 调用 Claude Sonnet 4.6 生成答案，
  Cohere Embed Multilingual v3 生成向量，Python 使用 boto3。
  GPT 辅助开发代码与项目运行时生成模型是不同职责。
- **替代方案**：直接调用模型供应商 API、更便宜的生成模型、本地部署模型。
- **收益与代价**：统一 AWS 角色与账单、无需 GPU；受区域、账户权限、配额和模型费用约束，
  Claude 不是最低价承诺，中文嵌入效果也尚未由本项目证明。
- **验证或复查**：接入前检查可用性、价格和跨区域处理，再用真实问题比较中文质量与成本。
  本步不联网重新核实这些动态信息。锁定实际模型标识、参数与提示词版本后才作为基线；
  换嵌入模型需重建索引，换模型或增加付费实验先说明并获得允许。

## ADR-010：单机 AWS 与按需启停

- **背景**：仅个人使用，需部署学习但不要求全天在线；用户接受按需启动 EC2。
- **决定**：EC2 Linux x86 + Docker Compose；Caddy 提供 HTTPS、React 静态文件与 API 代理。
  PostgreSQL、Qdrant 使用持久化存储，S3 归档与备份；保留 ECR、SSM、CloudWatch 等必要服务。
  Terraform 定义基础设施，具体资源在部署前审阅。
- **替代方案**：Lightsail 套餐、Lambda/API Gateway、App Runner/Fargate、托管数据库。
  这些没有被证明在本项目完整负载下更便宜，暂不替换主线。
- **收益与代价**：便于理解完整部署且可控制计算时长；需要启动等待、单机维护和恢复演练。
  停止 EC2 不等于 EBS、地址、备份等资源免费。
- **验证或复查**：验证区域、域名、证书、稳定地址、实际内存和预算；
  数据恢复与镜像回滚分别验收。若实际费用或启动体验不可接受，再比较完整方案的总成本。

## ADR-011：只允许个人访问

- **背景**：用户取消同事使用，但明确保留部署与鉴权。
- **决定**：Cognito 单用户，关闭自助注册；后端处理 OIDC、维护服务端会话，
  浏览器使用安全 Cookie；FastAPI 对业务 API 验证身份与访问权限。
  Cognito 用户、EC2 实例角色、GitHub 发布角色分别管理。
- **替代方案**：仅隐藏页面、只保护前端、公开 API、在浏览器保存 AWS 密钥；这些不满足需求。
- **收益与代价**：不自建密码存储，前后端同站点简化访问边界；
  登录回调、Cookie、CSRF、退出与过期处理仍需实现和测试。
- **验证或复查**：未登录、错误用户、过期会话、退出和绕过页面直调 API 均需验证。
  扩展用户范围需要新的需求确认，不预建多租户或角色管理平台。

## ADR-012：质量检查与渐进交付

- **背景**：本地 Windows 与云端 Linux 都需要可复现验证，并保留学习和实验依据。
- **决定**：pytest 运行现有 unittest；Ruff 检查 Python，GitHub Actions 在 push/PR 检查。
  当前 CI 仅只读仓库，固定 Action SHA、按锁文件安装，不使用模型或 AWS 秘密。
  后续发布才接入 OIDC、ECR、SSM、健康检查与回滚，不把 CI 成功等同部署成功。
- **替代方案**：仅人工检查；提前建立复杂发布平台；为无业务变化的文档重复运行全部检查。
- **收益与代价**：检查可自动复现；需要维护规则、依赖与测试，并承认覆盖率不等于业务正确率。
- **证据与复查**：A7 已有 [成功 CI](https://github.com/WeiliangJia/CarKnowledgeRAG/actions/runs/41590373866)，
  17 项测试和 11 个子测试通过。后续评测另建 120 题基线，开发集与保留测试集分开；
  自动评分仅辅助，关键配置仍需确定性校验与人工核验。
